# 万象一体化运行架构 · v0.3

## 架构决定

万象只有一个产品、一个本地进程、一个浏览器入口和一套持续工作流。任务理解不是外置页面或固定表单，而是从第一条消息开始的原生对话；用户确认工作说明后，同一个会话原位进入制作与验证。

底层 Agent 内核作为内部实现随项目精确锁定和安装，不作为用户需要理解、安装或操作的第二个产品。万象使用独立数据目录，不读取电脑中其他 Agent 工具的配置、插件或会话。

## 逻辑架构

```text
万象本地应用（localhost:3000）
├── 任务对话：自适应追问 + 七项动态工作说明
├── 制作验证：同一会话中的模型、工具、文件与运行证据
├── 万象策略：工作契约、安全边界与制作验证循环
├── Data Agent Bridge：受控的数据能力面
└── 社群抽屉：流程外的咨询与反馈服务
```

理解与制作共享同一个侧栏、工作区和会话系统，不进行跨端口、跨界面或跨角色跳转。

## 运行时边界

- 根命令 `pnpm start` 启动唯一的万象工作台。
- 项目随包安装并精确锁定内部运行时版本，不依赖本机源码目录。
- `.wanxiang-runtime/engine` 保存万象自己的配置、凭据与会话索引。
- `.wanxiang-runtime/projects` 保存 Agent 无法直接写入的权威项目状态。
- `.wanxiang-runtime/workspaces` 保存用户项目和生成产物。
- 产品配置关闭第三方默认品牌、插件清单、无关测试插件和第三方身份提示。
- 第三方许可保留在 `THIRD_PARTY_NOTICES.md`，但第三方产品身份不进入万象 UI 或模型人设。

## 工作区契约

每个工作 Agent 都有独立、可版本化的工作区：

```text
workspace/
├── AGENTS.md
└── .wanxiang/
    ├── project.json
    ├── work-brief.md
    ├── agent.json
    ├── data-contract.json
    ├── workflow.json
    ├── evals.json
    ├── runs/
    └── releases/
```

工作区路径是项目身份的一部分。`.wanxiang/project.json` 是可审查、可迁移的镜像；运行时受保护目录中的状态才是唯一写入事实源，避免制作工具绕过 CAS。首次导入可以由镜像恢复，但不得覆盖已经存在的权威状态。

工作说明生效后，同一个万象根会话通过受控生成工具提交确定性 Workflow、输入/输出 JSON Schema 和一个任务专属冒烟案例。Host 从已确认快照写入 `agent.json`、`data-contract.json`、`workflow.json` 和受保护 Eval，不接受调用者自报工作说明版本。Agent、Workflow、Eval 和运行证据共同记录工作说明修订；默认能力固定为当前项目、无网络、无外部副作用。客户跟进五案例只作为旧代理垂直切片与平台回归夹具，生成其他工作 Agent 时不会复用其字段。

## 工作简报一致性

工作说明包含目标、真实输入、代表案例、规则、交付物、边界和验收标准。模型可通过受控工具提交稀疏更新，但只能由用户点击“开始制作”确认当前版本；确认时保存独立快照并原子生成 `.wanxiang/work-brief.md`。

确认期间使用状态版本与修订号防止多标签覆盖。确认后的草稿修改不会改变现行工作契约；用户明确“同步修改并继续”后才生成新快照。会话正在运行或等待审批时不得切换写权限。

## 万象 Agent

万象始终使用同一个 Agent 和同一个会话，在同一个循环中完成：

1. 理解阶段只读用户明确选择的材料，并随对话更新工作说明。
2. 用户确认后读取已确认工作说明与数据契约。
3. 选择最小可用切片并实现。
4. Workflow 每次修改后立即通过同一个评测工具运行当前修订的全部代表性案例与边界案例；成员也可在证据面板手动重跑。
5. 根据证据修正，直到成员能够判断结果是否可用。
6. 对外写入、发送、删除和付款等动作始终先预览并获得明确批准。

系统提示词只使用万象身份和策略；运行时上下文、工具与权限机制继续保留。

当前客户跟进能力是代理垂直切片。它以固定 `asOf` 日期读取合成客户 CSV 和沟通 JSON，输出 Markdown 周报与结构化漏跟进清单。受保护 Eval 包含五个代表案例；代理运行按客户身份、原因码与关键证据精确验证结构化结果，只检查 Markdown 的必要章节和引用，不把全文快照当作验收标准。会话 Projection 分别保留五个案例的实时状态与证据，但不承担跨会话聚合；受保护项目状态按 `runId` 保存不可变尝试、版本、逐案例结论和重试谱系，并派生工作区镜像。浏览器刷新从受保护状态恢复抽屉；runtime 新实例读取到旧实例遗留的未完成运行时，将其明确恢复为 `interrupted`，不会提升为通过。该切片不构成影子运行或真实运行。

## Data Agent Bridge

Data Agent Bridge 是万象访问业务数据的唯一能力面。模型只能看到经过裁剪的能力描述和结果，不能直接持有业务凭据。读取与写入分开授权；每个结果包含来源、时间、动作摘要和可追踪 ID。

当前 MVP 只有示例数据契约，因此不得声称已经连接真实数据，也不得执行外部写入。

## 社群服务

社群以侧边抽屉存在，可用于咨询问题和提交反馈。它不进入 Agent 流程，不解锁阶段，不替成员确认需求，也不决定验收结果。

## 安全与运营

- 新会话默认只读；只有用户明确开始制作后才允许当前项目写入，高风险动作需人工批准。
- 本地服务只绑定回环地址；工作简报写入接口校验同源请求、字段和大小。
- 会话、凭据和临时运行产物不进入 Git。
- 依赖版本、原生模块和第三方许可随发行包固定并验证。
- 版本升级必须通过语法、单元、启动、浏览器交互和完整项目回放。

## 第一条垂直切片

1. 成员从最近一次真实任务和一份真实材料开始对话。
2. 万象按需追问，并用受控工具形成七项工作说明。
3. 成员确认后，当前会话安全切换到项目可写并原位开始制作。
4. 万象创建最小实现并运行至少 5 个案例，其中至少 2 个为边界案例。
5. 真实数据接入前只做明确标注的代理运行；影子运行必须等待真实输入并与成员原有做法并行比较，达标后再逐步扩大自动化权限。
